# 课题人数未汇总下属研究单元：问题报告

日期：2026-11-27。修复目标：finance-portal。本文与测试仅描述结构及虚构案例，不含真实名单。

## 现象与原因

双选页可出现课题显示 1 人、其下研究单元分别显示 2、4、1 人。原 api.recruit 和 api.project 的 members 都仅按 project_member.project_id = 当前项目统计，未包含 parent_id 指向该课题的研究单元。此值是直属名单人数，却被呈现为课题成员总人数。

## 修复规则

课题人数取直属名单与所有有效下属研究单元名单的账号并集；研究单元只统计本单元。同人跨多个研究单元、同时在课题直属名单中都只计一次，不相加各单元人数。只统计启用账号、已生效且未退出的关系；退出日当天起不计。下属项目须 active、已立项、非公共项目。负责人不自动额外加一人。

新增只读计数函数供双选视图和课题视图复用。members 返回汇总数，追加 direct_members 保留直属数；前端注明「含下属研究单元，已去重；直属 N 人」。课题详情原成员表改标「直属成员」，避免误认成汇总名单。

只改只读统计；不补写父课题成员、不改 is_on_project、支出/资源权限、名义币、实际币、份额与审批。人员双选名单中的实际归属关系也不复制为父课题关系。

## 验收案例

虚构课题直属甲，单元一甲和乙，单元二乙和丙，单元三丙：课题为 3 人（直属 1 人），三个单元分别为 2、2、1 人。历史退出、未来加入、停用账号、不生效子项目及其他课题成员不影响总数。丙退出所有下属单元后总数变为 2。乙不会因此获得父课题直接成员资格或管理权限。未登录不可读取双选数据。
