# Supabase 读模型方案

## 定位

Supabase 仅作为高频查询读模型或缓存数据库；飞书仍是当前业务事实源。当前不迁移生产数据、不改变写入路径、不切换线上页面主数据源。

## 适合首批 PoC 的数据

- 项目基础信息和非敏感状态。
- 项目预算汇总、支出汇总和执行率快照。
- 支出分类、优先级规则、模型目录等低敏配置。

## 不宜公共缓存的数据

- 用户权限、会话信息、个人申请。
- 审批中的申请、资产领用明细和支出明细。
- 附件索引、API Key、密钥和任何敏感凭证。

## 同步模型

```text
飞书写入成功 -> 生成幂等事件/同步任务 -> Supabase upsert 读模型
                                 -> 失败重试/补偿
页面查询 -> Worker 权限判断 -> 读模型（允许明确标记最终一致）
```

同步必须携带业务 ID、实体类型、版本/更新时间和来源记录 ID；删除采用软删除或状态传播。同步失败不能阻断正式业务写入，必须可重试、可观测、可重放。

## 区域和容量风险

当前 Supabase 位于 Oceania/Sydney，Compute 为 nano。投入线上前必须实测用户区域、Cloudflare Worker 执行位置到 Sydney 的 RTT，并检查连接数、CPU、内存和数据库响应。不能仅凭“Supabase 比飞书快”做切换结论。

## PoC 验收

选择项目列表或低敏配置：并行测量 Worker→飞书与 Worker→Supabase 的 P50/P95、错误率、响应体大小、同步延迟和故障恢复时间。只有在一致性校验和性能收益均明确后，才讨论扩大范围。
