# 双选人事一键私信提醒

## 目标与入口

双选名单默认折叠，展开后人事可一键预览并确认发送。普通成员、负责人和只有人员查看权限的账号不显示按钮，也无法直接调用发送接口。新增全局权限 selection.remind，仅赋予现有人事角色，不改其他基础角色。

## 收件规则

以现有人员档案 rank=intern、在岗或非编、尚未加入有效课题或研究单元为准。无意向提醒尽快在正则表达意向，已表达意向提醒主动联系负责人、沟通小任务。Assistant 和其他身份不发学生提醒，包括 Assistant 硕士。

有上述 Intern 有效未处理意向的负责人聚合一条私信，列出对应课题/单元，提醒联系并确认是否接收，接收后加入名单。当前没有单独的接收名额字段，不能推测哪些负责人还缺人；本功能依据待处理意向定位待接收事项。无有效意向不提醒所有负责人。不会自动同意、自动加人或替代沟通。

未关联账号、停用账号、未绑定飞书、负责人未明确、本人经办及今日已入队者显示跳过原因，不按姓名或外部邮箱猜收件人。

## 执行与可追溯

预览及发送均由服务端计算，客户端不能传收件人或文案。确认时重新核对当前成员与意向。仅写入既有 feishu_outbox，沿用正则的私信卡片和跳转按钮；无群消息，不从此 RPC 直接调用飞书。原通知服务启用 FEISHU_NOTIFY=on 后按既有机制发送，入队不等于送达。

selection_reminder_log 保存收件账号、类型、北京时间日期、发起人、时间和发件记录。事务锁及唯一约束限制同账号同类每日最多一条；点击多次、多位人事操作同样去重。只向 API 角色暴露预览与发送函数，内部目标函数及日志表不直接开放。没有后台定时批量催办，本功能由人事按钮触发。

## 部署和验证

先执行 0153_selection_reminders.sql，再发布 Worker 与前端；不依赖尚未合并的人数汇总 PR。无需新增飞书凭证或连接器，名单及日志留在数据库，不进入公开仓库。真实飞书实发由上线后授权人事核验，本地测试仅在内存队列写入虚构消息。

测试接入 npm test，覆盖身份/状态筛选、负责人聚合、未关联与未绑定、无权限 RPC 拒绝、重复触发幂等、预览后状态变化重新核对、私信队列与日志一致。
